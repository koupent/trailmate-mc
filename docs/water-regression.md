# 水中追従・生存の回帰検証

## 旧版の不具合を同じ箱庭で再現

v0.1.41 の本番コードに、新しい水中ステージと独立した酸素・溺水時計を接続して確認しました。

| ステージ | v0.1.41 | 修正後（180秒） |
| --- | --- | --- |
| 1ブロックの浅瀬 → 深場 → 岸 | X=3.93で停止し、反対岸に到達しない | 反対岸へ上陸、HP20、溺水ダメージ0 |
| 水中の天井・離れた空気 | 天井の下で浮上し続けて溺死 | 天井の横にある空気へ帰還し、回復後に再追従、溺水ダメージ0 |

旧テストは酸素を5に固定して12秒間泳がせ、最後に15へ書き換えていました。酸素の減少や溺水ダメージを計算せず、岸からの入水・段差・天井も含めていなかったため、この不具合を検出できませんでした。

## 実行するもの

`WaterSimulation` は本番の `CompanionContext` / `CompanionOrchestrator` / `FollowMode` / `HazardEscapeController` / `MovementController` をそのまま使います。実際の `mineflayer-pathfinder` プラグインと `prismarine-physics` を動かし、制御入力が地形上の移動になるところまで閉ループで検証します。

Botの判断は4Hz、物理・ステータスは20Hzです。サーバー側の境界として、酸素300tickの消耗、水面での回復、酸素切れ時の溺水ダメージ、有限の食料を32tickで消費する処理、空腹・自然回復をモデル化します。食事の開始条件と選択は本番の共通関数を使います。テスト途中でBotを移動させたり、酸素を補充したりしません。

水泳速度は同じ物理エンジンで水平約2.0、上昇約3.5、下降約0.5ブロック/秒と実測し、見積もりにはそれぞれ1.6、2.0、0.4を使います。潜る次の区間の移動時間と、そこから呼吸できる地点へ戻る時間を加え、さらに4秒の酸素を残します。実測より速い値を使っていないこともテストします。

| 検証 | 確認する結果 |
| --- | --- |
| 1・2ブロックの浅瀬 | 岸から入水し、深場を通り、反対岸の1ブロックの段差を上がる |
| 深さ30ブロック | 移動するオーナーへ水平に進み、酸素の範囲内で潜る。届かない深度へは無理に潜らない |
| 水中の天井 | 天井を空気扱いせず、横へ迂回して実際に呼吸できる帰還座標へ戻る |
| 負傷・空腹 | 浮上を優先し、食事・回復が済んでから追従を再開する |
| 食料なし | 回復できない状態で再潜水せず、水面を保つ |
| 水草 | 海草・昆布を水中として通過する |
| 未読込チャンク | 未知のブロックを空気扱いせず、その先へ潜らない |
| 待機への切替 | 水泳の移動入力を解除する |
| シミュレーターHTTP API | UIと同じ読込・再生APIで浅瀬2種・深場・天井を各180秒実行する |

基本6ステージは各180秒、溺水ダメージ0、酸素の余裕が残ること、帰還と再追従が繰り返されることを検証します。失敗時も `WATER_REPORT_DIR` に座標・HP・酸素・入力・帰還先の時系列JSONを保存できます。

## 実行と公開の条件

```sh
npm run test:water
WATER_REPORT_DIR=data/water-regression npm run test:water
npm run sim
# http://127.0.0.1:4173/water.html
```

リリースworkflowの `verify` は型チェックと全テスト（水中E2Eを含む）を実行し、成功するまでGHCRとWindows ZIPの公開ジョブを開始しません。ログはActionsの `water-regression` artifactに保存します。

実ブラウザーでも浅瀬・天井ステージを読込・再生し、3D表示とステータス更新、帰還と再追従、溺水ダメージ0、JavaScript例外なしを確認しました。

## 追従そのもの・本番との差の追加検証

生存や最終到達だけでは追従の品質は保証できません。水中での往復・曲線移動では、通常追従中の距離、3秒以上の硬直がないこと、反転したオーナーへ戻ることを検証します。岸への移動では、オーナーが岸のすぐ近くで停止した場合も、Botが着地し、その後に動き回らないことを検証します。既に追従距離内の浅瀬で1.66ブロック動く旧動作を再現し、不要なセル中央への移動を止めました。

さらに実際のMineflayer物理プラグイン・制御入力・物理更新イベント・本番のパケット送信処理をつないだテストで、潜水・水平移動が位置パケットにも反映されることを検証します。位置と視線の送信が混在したときの座標消失・古い座標の再送も検証します。管理画面は実際の浮上中のFSMを使い、一時的に状態取得が失敗しても「更新待ち」として図を保持し、明示的な未スポーン応答では消去することを検証します。

また、固定タグの旧インストールから更新した際に、実際のコンテナイメージ・版の環境変数・再起動用Composeの固定タグがすべて新しい版になることを検証します。旧版のダッシュボードは自分自身を旧タグで再取得するため、最初の切替には新しいZIPの上書き展開が必要です。

この検証はMinecraftサーバーに接続するテストではありません。サーバー独自のスタミナ、ViaProxy固有の補正、ラグ、特殊な水流や状態効果は再現していません。酸素に対して帰還経路が長すぎる場合は追従を中断する設計です。
